01 — Топология

Пять слоёв, один инвариант

Запросы входят через driving-адаптеры, спускаются к домену через порты, выходят наружу через driven-адаптеры. Каждая стрелка ниже — это направление, в котором может течь вызов; назад через слои домен не знает ничего.

02 — Правило

Единственный инвариант, который держит границы

⬡
Адаптеры (CLI / Tauri / HTTP) ──▷ маппят DTO ──▷ доменные порты Домен (bc-*) ──▷ только через порты ──▷ никогда std::process напрямую Нарушение = красный fitness-тест. Новый инвариант = новый тест.
03 — Порты

Три канонических порта — плюс три ratchet-guarded seam-адаптера

bc-build/src/command_exec.rs
CommandExecutor
внешние бинари — docker, emerge, git
bc-deployment/src/orchestrator.rs
DeployProvisioner
деплой-скрипты через PTY
bc-mesh/src/helm_port.rs
HelmExecutor
helm через PTY

Ultracode-анализ архитектуры (2026-07-23) нашёл ещё 3 легитимных, но раньше незадокументированных точки прямого Command::new: core/adapters.rs + core/cancellation.rs + core/repository/mod.rs (сейчас под собственным ratchet-тестом fitness_ratchet_core_no_new_command), плюс единые seam-файлы cli/process.rs и bc-baremetal/process.rs. Итого 6 задокументированных точек I/O, не 3 — CLAUDE.md обновлён.
