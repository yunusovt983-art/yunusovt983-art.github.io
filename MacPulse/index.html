MacPulse

Монитор в строке меню, отвечающий на один вопрос: этот Mac сейчас захлебнётся? Сделан для тех, кто гоняет тяжёлые AI-нагрузки, где память кончается быстро, а первым признаком беды обычно оказывается уже подтормаживающая машина. Показывает то, чего не показывает никто: расход токенов локальных сессий Claude Code.

Карта компонентов

Приложение без окон: LSUIElement, вся жизнь — иконка в строке меню и попап под ней. Два независимых источника данных живут в отдельных акторах, потому что их время отклика несопоставимо: системные счётчики отдаются за миллисекунды, а сканирование чужих jsonl-транскриптов — время, которое приложение не контролирует.

Жёлтым — путь, по которому идут данные к экрану; красной рамкой — акторы, сериализующие доступ к системе; пунктиром — единственное место, где используется недокументированный API.

Цикл опроса

Порядок внутри одного тика важнее его длительности. Токены считаются параллельно с самого начала, но снимок публикуется и пороги проверяются, не дожидаясь их.

Раньше алерт о памяти ждал окончания чтения транскриптов — а у одной сессии «хвост» доходил до 117 МБ. Предупреждение о нехватке памяти, приходящее после сканирования чужих файлов, опаздывает ровно в том сценарии, ради которого написано.

Два вывода, изменившие план

Перечисление умирает, чтение — нет

proc_listpids возвращает ноль, а не урезанный список. Но proc_pidinfo на уже известном PID отвечает — значит источником PID становится NSWorkspace.runningApplications.

Плата конкретная: в этот список попадают только зарегистрированные приложения. CLI-процессы, включая сам claude, — никогда. Песочная сборка видит 1,4 ГБ из реальных 12.

Учёт токенов выживает

С временным исключением files.home-relative-path.read-only на /.claude/ читаются и каталоги, и содержимое транскриптов. Отличающая продукт функция сохраняется.

Понадобилась одна правка: homeDirectoryForCurrentUser в песочнице отдаёт контейнер, поэтому настоящий дом берётся через getpwuid.

Конвейеры раздачи

Два канала, а не две ступени одного. Developer ID и App Store используют разные сертификаты и взаимоисключающие шаги.

Developer ID — прямая раздача

  1. Сборка и тесты
  2. Подпись Developer ID Application + hardened runtime
  3. Нотаризация у Apple, ожидание вердикта
  4. Стаплинг тикета в бандл
  5. ZIP и DMG с алиасом на /Applications
  6. Подпись и нотаризация самого DMG
  7. GitHub Release по тегу v*
Проверка — spctl на распакованной копии с карантином: так, как это сделает чужой Mac.

App Store

  1. Сборка с MACPULSE_APP_STORE=1
  2. Вложение provisioning profile в бандл
  3. Подпись Apple Distribution, без hardened runtime
  4. productbuild → .pkg, подпись installer-сертификатом
  5. Валидация пакета у Apple
  6. Загрузка в App Store Connect
Нотаризации здесь нет: её выполняет Apple после загрузки. Отправлять пакет в notarytool — потерянное время.

Зачем DMG, если ZIP уже есть: из архива приложение запускают прямо из ~/Downloads, macOS включает App Translocation, и SMAppService записывает в автозапуск эфемерный путь — «Launch at Login» тихо перестаёт работать после перезагрузки. Алиас на /Applications делает правильный шаг очевидным.

Найдено замерами

Дефекты, которых не видно в коде — только на работающей машине.

Гонка в чтении датчиков

ThermalSensors кэшировал клиент IOKit в статическом поле без синхронизации. Два параллельных опроса ломают os_unfair_lock внутри самого IOKit, и процесс умирает мгновенно — вместе с алертами о памяти, ради которых запущен.

От этого спасала лишь компоновка: одна view model — один актор — сериализованные вызовы. Случайность, а не гарантия.

Легенда шире попапа

Четыре подписи с числами в строку дают ~342pt при ширине 340. .fixedSize() не давал SwiftUI перенести их — он обрезал, и последний сегмент уезжал за край.

342 против 340
Попап нельзя было увидеть

Строкой меню владеет системный процесс, поэтому попап не снимает и не кликает никакая автоматика. Каждая правка интерфейса упиралась в «попроси кого-нибудь посмотреть».

Флаг --debug-window показывает то же содержимое в обычном окне; ещё один флаг закрыл проверку автозапуска без единого клика.

Приватность проверяемая

Приложение не содержит сетевого кода, не линкует ни одного сетевого фреймворка и ничего не пишет на диск, кроме закладки безопасного доступа в контейнере — и то лишь если пользователь сам выдал доступ к папке. Это не заявление о намерениях: всё три проверяется на артефакте.

Данные, которые оно читает — счётчики ядра и транскрипты, которые Claude Code и так пишет на этой же машине, — остаются на ней.
